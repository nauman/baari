baari

What
do I
owe?

baari keeps one machine-local registry of every repo you work in, and gives you a single view of what you owe a reply to — and what you're waiting on others for.

Language- and framework-agnostic. It reads conventions in your repo, not your code — the same whether a project is Rails, Go, Node, Python, or plain documentation.

baari next 
$ baari next

OWED BY ME (2)
  ~/code/api       threads/rate-limit-design      4d
  ~/code/web       threads/session-cookie-scope   1d

4 repos registered · 1 waiting on others · 0 stale

The problem

Coordination state scatters. A note here, a thread there, a script in each project that only knows about itself.

Once you're working across several repos, there's no single place to ask the only question that matters when you sit down: what's actually waiting on me? You end up checking five directories by hand, or trusting memory.

What it does

01

baari status

Cross-repo view of what you owe a reply to, and what you're waiting on others for.

02

baari next

Just what's owed right now, across every registered repo. Nothing else.

03

baari registry

List, prune, forget, or ignore the repos baari knows about. Repos register themselves the first time you run baari inside one — there is no manual setup step.

04

baari doctor

Validate machine and repo state: registry integrity, identity, and convention markers.

05

baari thread

Inspect and scaffold coordination threads, and flag ownership assigned to names that don't exist in the owning repo.

06

baari whoami

Show the identity baari resolves for "who is me", and where it came from.

Install

Homebrew

brew install nauman/tap/baari

Without Homebrew

curl --proto '=https' --tlsv1.2 -fsSL https://nauman.github.io/baari/install.sh | sh

First run

baari identity set <your-alias>
baari status

Configuration

The tool ships mechanism. Your repo owns its canon.

Checks read their thresholds from a .baari.yml at your repo root, walked up from the working directory. Nothing project-specific is compiled into the binary — no vocabulary, no paths, no rules of ours.

With no config file, every check runs with zero allowances and warns rather than fails. A tool that fails on first run in a stranger's repo is hostile; one that stays silent is useless. Use --strict in CI to give it teeth.

What baari is not

  • Not a task manager. It reports what your repos already say, and invents no work of its own.
  • Not a server. Everything is local; there is no account, no sync, and no network call.
  • Not framework-specific. It never reads your source code, only repo conventions.
  • Not opinionated by default. With no config, it warns and allows nothing to fail.
